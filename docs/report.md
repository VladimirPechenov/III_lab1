## 1. Цель работы

Реализовать и сравнить два способа управления NPC-стражником: конечный автомат (FSM) и дерево поведения (Behavior Tree). Проверить патрулирование, обнаружение игрока с учётом препятствий, задержку перед преследованием, атаку и поиск потерянной цели.

## 2. Постановка задачи

Стражник проходит четыре точки патруля в комнате 20 × 20 м с четырьмя препятствиями. При появлении игрока в конусе зрения он ждёт 1 секунду, затем преследует. На расстоянии не более 1,5 м выполняет демонстрационную атаку. Если цель не видна 2 секунды, ищет её вокруг последней известной позиции. Поиск прекращается через 10 секунд. Алгоритм переключается в компоненте `GuardMode` в инспекторе.

## 3. Реализация

`Perception` проверяет дальность 10 м, угол обзора 90° и луч до игрока. Слои игрока и стражника исключены из маски препятствий, поэтому их коллайдеры не перекрывают луч. `GuardMotor` выполняет движение через `NavMeshAgent`: переход между waypoints, погоню, обход последней известной позиции и остановку для атаки. Состояния FSM реализованы явным `switch` в `GuardFSM`. Дерево поведения в `GuardBT` состоит из `Selector`, `Sequence`, `Condition` и `Action`; порядок ветвей задаёт приоритет действий. Время тревоги, потери и поиска задаётся через инспектор.

Атака выводит сообщение в Console с интервалом 1 секунда. Урон и здоровье игрока не входят в постановку задачи. Игрок перемещается клавишами WASD. Демонстрационная сцена создаётся пунктом меню **Lab 01 → Create demonstration scene**; генератор также запекает NavMesh и добавляет сцену в Build Settings.

Диаграммы FSM и BT: [diagrams.md](diagrams.md).

## 4. Демонстрация

Ссылка на видео: [добавить]. В записи нужно показать оба режима в инспекторе и последовательность Patrol → Alert → Chase → Attack → Search → Patrol. Для проверки препятствия надо поместить игрока за одним из блоков и показать, что стражник не видит его через стену.

## 5. Проверки и результаты

| Сценарий | Ожидаемый результат | Статус |
|---|---|---|
| Патруль | движение по четырём точкам | требуется запуск в Unity |
| Зрение | цель за препятствием не обнаружена | требуется запуск в Unity |
| Тревога | переход к Chase через 1 с видимости | требуется запуск в Unity |
| Атака | сообщение в Console в пределах 1,5 м | требуется запуск в Unity |
| Потеря и поиск | Search после 2 с, возврат через 10 с | требуется запуск в Unity |
| Узлы BT | `Selector` и `Sequence` соблюдают приоритет | добавлены EditMode-тесты |

Результаты не отмечены как пройденные без фактического запуска редактора. При сдаче следует записать наблюдаемые результаты и скриншоты после проверки.

## 6. Выводы

FSM удобно читать по явным состояниям и переходам. BT выражает приоритет действий последовательным обходом ветвей. Общие сенсор и управление агентом позволяют сравнивать архитектуры в одинаковых условиях сцены.
