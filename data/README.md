# Данные лабораторной работы № 2

- `telemetry.db` — готовая SQLite-база: 48 учебных сессий, 24 игрока, 256 событий.
- `events.jsonl` — та же выборка до записи в SQLite.
- `unity-capture.jsonl` — сохранённые события двух проверочных игровых сессий L1/L2.
- `live.db` — новые события, принимаемые локальным сервером; не хранится в Git.
- `unity-events.jsonl` — текущий журнал Unity; не хранится в Git.

Учебная выборка имеет источник `simulation`, фиксированный seed 42 и даты 1–4 октября 2026 года (UTC).
Все 24 игрока посещают игру повторно, но только 12 на следующий календарный день: это позволяет
различить D1 и долю игроков с двумя сессиями. В каждой сессии есть начало и конец; часть сессий
не достигает контрольной точки или выхода.

Два уровня используют одинаковую комнату 20 × 20 м с четырьмя блоками. L1 использует FSM, L2 — BT
и повышенную скорость стражника. Генератор задаёт группы смертей на разных открытых участках комнаты
для проверки отдельных тепловых карт. Выборка не является наблюдением 24 реальных игроков.

Воспроизведение:

```powershell
python -m client.python_logger --simulate 48 --seed 42
python -m analysis.analyze
```

События имеют стабильные идентификаторы, поэтому повторный импорт не меняет число записей.
Для импорта проверочных сессий в отдельную базу:

```powershell
python -m client.python_logger --import-jsonl data/unity-capture.jsonl --db data/live.db
```
